# LightHouse OS 1.3.0

LightHouse OS 1.3.0 introduces the Adaptive Engineering Loop: a compact engineering policy layer that improves the existing autonomous Brain instead of creating a parallel coding system.

## Adaptive engineering

The main AI now treats the active repository implementation, entry points, tests, contracts and current Diff as primary evidence. It is strongly guided to improve, extend or refactor existing code before creating replacement copies, while retaining the engineering freedom to extract modules or replace an implementation when evidence shows that doing so is materially cleaner and safer.

Planning, Agent delegation, Build Cells and Worktrees remain optional strategies selected by the main AI. They are not fixed phases or keyword-routed workflow gates.

## Completion candidates

A model `final` response is now a completion candidate rather than an unconditional success transition. Objective operation failures, missing post-change Diff inspection and missing proportional validation are returned to the same main AI as durable engineering evidence. The AI can gather more evidence, revise the implementation, or intentionally finish with a visible warning after considering advisory guidance.

## Run-wide Auto

The first Auto confirmation now authorizes every subsequent governed capability in the same Run across all Data, System and Desktop targets attached to the Workspace. This includes explicit and passkey-governed operations. Authority ends when the Run completes, is cancelled or Auto is explicitly disabled.

Workspace and target binding, actor identity, allowed roots, immutable operation arguments and Receipts remain enforced by the Operation Kernel.

## Elastic execution budget

Engineering Runs start with a larger soft budget and may extend toward a hard ceiling while verified progress continues. Repeated behavior without new evidence does not earn more budget.

## Structured context compaction

Oversized model state is compacted by semantic section. Current goals, Workspace facts, engineering state, recent and pinned steps, relevant memory, Agent status and verified evidence are prioritized. LightHouse no longer falls back to deleting the entire middle of the state as one raw head/tail slice.

## Compatibility

No PostgreSQL migration is required. Existing Workspaces, Targets, Operations, Receipts, conversations, Memory Fabric state, Agent Bus state and Mega Project state remain compatible.
